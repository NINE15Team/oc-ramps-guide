CLIENT HANDBOOK · QA THEME · 24 SEPTEMBER 2026

Keep your site up to date, with confidence.

A practical guide to editing OC Ramps, understanding where content comes from, and knowing when to call a developer.

Start with the right theme. In Shopify Admin, go to Online Store → Themes and choose Customize on the theme named QA. Before launch, QA may be unpublished; changes to the live theme will not appear in its preview.

02 / WORDS TO KNOW

Four building blocks

ThemeThe design and code. QA is the theme documented here.
TemplateA page recipe, such as Product or Contact. Many pages can share one template.
Section / blockA visible area and its smaller pieces in the Theme Editor.
Metafield / metaobjectAn extra field on an item / a reusable record with several fields.

Think of the page as template layout + Shopify content + optional extra fields. Changing a shared metaobject can update several pages at once.

03 / CONTENT MANAGEMENT

Pages, posts and media

Add or update a page

  1. Open Online Store → Pages; choose a page or click Add page.
  2. Edit title and body. For a new page, choose the intended Theme template (for example Contact or FAQ). The default page template is simple.
  3. Set the URL and search listing in Search engine listing. Save.
  4. If visitors need a menu link, add it under Menus. Preview the page in QA on desktop and mobile.

Remove or hide content

To temporarily hide a page, remove its menu link or unpublish it when Shopify offers that option. To remove a post, use its publish controls first; deletion can break links. Add a URL redirect if an old URL changes.

Upload media

  1. Use Content → Files for reusable files, or the image picker in a product/article/section.
  2. Use a clear file name and useful alt text describing the image. Keep images appropriately sized and compressed.
  3. Replace an image in the content source that owns it; changing an unrelated theme image will not update a product metafield image.

Add a blog post

  1. Open Content → Blog posts → Add blog post.
  2. Choose the correct blog, add title, body, featured image, author, excerpt and relevant tags.
  3. Choose the matching article template if the post needs a special layout. Set SEO title and description, then publish or schedule.
  4. Open its blog listing and article page to check badges, filters and related content.

04 / CATALOG

Products and collections

  1. For a new product, complete title, description, media, pricing, variants, inventory and shipping in Products.
  2. Assign the right collections. Collection membership can also determine the shared PDP Profile when the product has no own profile.
  3. Fill product metafields such as custom.pdp_specs and custom.pdp_specs_subheading. Check the product page and cart.
  4. For a collection, edit its title, description, image, product rules/manual products and SEO. The QA collection template contains hero, filters, grid and optional comparison.
Shared copy warning. If a collection has a PDP Profile, changing that record may affect every product inheriting it. Give a product its own profile for a one-off override.

Collection comparison can use custom.dimensions, then fall back to custom.pdp_specs. The featured article section on article pages can use custom.featured_articles before editor-selected articles.

05 / DYNAMIC CONTENT

How the automatic content works

Product or page in Shopify→ metafield points to a record→ QA template reads it→ visitor sees the result

Product page: shared PDP Profile

The product template’s lower sections read a PDP Profile metaobject. First the theme checks the product’s custom.pdp_profile. If empty, it checks the product’s collections and uses the first collection with a profile. Collection order can matter when several collections have profiles, so assign a product-level profile if the result must be unambiguous.

  1. Open Content → Metaobjects → PDP Profile. Add or edit an entry. Fill intro, feature blocks, “What’s in the Box,” shipping cards, financing, FAQs and help fields as needed.
  2. Open Products → Collections → [collection] and assign the record in its PDP profile metafield. For a unique product, assign it under Products → [product] → PDP profile.
  3. Enter that product’s own Specs and optional specs subheading in product metafields. Specs can be a rich-text list or list entries; use Height|4 ft for a clean label/value row.
  4. Preview one inheriting product and one overridden product. Empty fields can hide entire sections, including features, specs, financing or FAQ.

  2. Paste the matching tag from an existing post in the same category.

07 / THEME EDITOR

Navigation, sections and widgets

Update navigation

  1. Open Content → Menus (some Admin versions say Online Store → Navigation).
  2. Edit the menu used by the header or footer. Add, reorder, nest or remove links; save.
  3. Open Online Store → Themes → QA → Customize → Header and verify the intended menu is selected. Check desktop mega menu and mobile drawer.

Edit a page layout

  1. In the QA Theme Editor, use the page selector at top to choose Home, Product, Collection, Blog or a specific page template.
  2. Select a section in the left panel. Edit its settings; use blocks for items such as slides, text, buttons and cards. Drag to reorder.
  3. Preview desktop and mobile; save only after checking links, images and spacing.

The theme’s homepage uses slides, collection and product lists, content sections and featured blog posts. Product pages use a buy box, profile-driven sections and recommendations. Blog templates use featured stories, post grids and filters. Header, footer, cart page, search, wishlist and comparison are shared components. A native cart drawer exists in code but QA is set to use the cart page.

Know the scope. Editing a shared template can change many pages. Duplicate the theme before large layout changes and confirm which template the page uses.

08 / SEARCH & MEDIA

Simple SEO checklist

  • Write a clear, unique page/product/article title and a useful search description in Search engine listing.
  • Use one visible H1 and meaningful subheadings. Put the main topic in natural copy, not repeated keywords.
  • Choose short, stable URL handles. When changing an existing URL, create a redirect under Online Store → Navigation → URL redirects or Admin search.
  • Add descriptive image alt text; compress large uploads and use appropriate image dimensions.
  • Link related pages and products. Check every CTA after an edit.
  • Preview social sharing and mobile appearance. Review indexing/analytics in the connected tools.

The QA theme no longer loads the old hard-coded Google Tag Manager container. Pull request #21 removed it from the theme layout. Tracking, if configured, should be checked in Shopify Admin → Settings → Customer events and the connected analytics apps. The theme repository alone cannot confirm which pixels are active or whether purchase events are reaching a destination. See Shopify’s pixel guide.

09 / ACCESS

Users and permissions

  1. Store owner opens Settings → Users (sometimes Users and permissions).
  2. To add a person, invite them by email and grant only the permissions needed for their work. A content editor usually needs products, content, files and theme access; finance and app access should be separate.
  3. To edit access, open their user record and change permissions. To remove access, deactivate/remove the user from that screen after transferring any owned work.
  4. Review staff and collaborator accounts regularly, especially after a project ends.

Only the owner should control billing, domains and top-level permissions. Require individual accounts and two-step authentication. Do not share a single admin login or place passwords/API keys in GitHub Pages or this repository.

10 / DEVELOPER REFERENCE

How QA is built

QA is a Shopify Online Store 2.0 Liquid theme. Shopify hosts the storefront, checkout and catalog. The repository contains Liquid templates, JSON template settings, CSS, JavaScript and locale files. Shopify Admin stores products, pages, posts, menus, metafield definitions and metaobject entries; there is no separate database schema or application server in this repository.

Visitor request→ Shopify template JSON→ Liquid section + blocks→ Admin data / metafields→ HTML, CSS and JS
FolderPurpose
layout/Outer HTML shell; the old hard-coded GTM snippet was removed in pull request #21.
templates/Page recipes and section settings. QA includes home, product, collection, cart, search, blog, article and many page variants.
sections/Large areas such as header, product info, collection grid, featured posts and glossary.
blocks/Smaller Theme Editor components inside sections.
snippets/Reusable Liquid; pdp-profile.liquid resolves shared product data.
assets/CSS, JavaScript, icons and fonts.
config/Theme settings schema and saved settings; app embed references.
locales/Translated UI strings.
tests/, scripts/Playwright smoke checks and helper scripts.

Theme JSON files can be changed by the Shopify Theme Editor. Before deploying code, pull the latest QA theme so an upload does not overwrite merchant edits.

Changing a key or app setting

  1. Find the owning app in Settings → Apps and sales channels or the vendor dashboard.
  2. Use that service’s secure credential rotation flow. Update the Shopify app connection, custom app credential or theme setting that references it.
  3. Test on the QA preview, then verify the live integration. Revoke the old key only after the new one works.

For tracking changes, have the account owner or analytics specialist review Customer events and the connected app configuration, then test the events. Avoid adding a second copy of the same tracking code to the theme.

13 / HOSTING & RELEASES

Hosting, deployment and rollback

Shopify hosts ocramps.com and serves the theme over HTTPS. Server capacity, TLS and checkout infrastructure are managed by Shopify. Domain registration and DNS provider are not verifiable from this repository; the store owner should record them in the private handoff.

Safest release path

  1. In Online Store → Themes, duplicate the current theme as a recovery point.
  2. Confirm which theme is named QA and whether it is unpublished. Pull its latest files before code changes so Theme Editor edits are included.
  3. Make a focused change on the QA Git branch, review the diff, and run relevant theme tests or a manual preview.
  4. Upload/push to the intended unpublished QA theme. Check home, product, collection, article, cart, search and mobile navigation.
  5. When approved for launch, publish QA from Shopify Themes. Record the theme ID, date and Git commit in the release log.

Repository: NINE15Team/OC-Ramps; branch documented here: QA. Access is granted through the repository owner’s GitHub organization, with named accounts and minimum permissions. This guide cannot grant that access.

Restore a previous version

  1. For a single recent editor mistake, use Shopify’s theme file version history where available or revert the relevant saved setting.
  2. For a full theme rollback, publish the duplicated prior theme in Online Store → Themes. Confirm checkout/cart and integrations afterward.
  3. For code rollback, have a developer revert the Git commit and deploy to the correct theme. Restoring theme code does not restore products, posts, menus or metaobject entries.

Shopify manages storefront SSL. If a browser reports a certificate issue, check Settings → Domains for connection status and DNS records, then contact Shopify support or the domain registrar. Record the registrar, DNS owner and renewal contact privately.

16 / GROWTH

What can grow easily?

  • Add products, articles and pages using existing templates; use metaobjects for repeatable, structured copy.
  • Add a new product family by creating a new PDP Profile and assigning it to a collection. Check each product’s specs.
  • Add new blog content using established tag conventions. A new filter/category or glossary category may need template/code changes.
  • Ask a developer for new page modules, data types, complex integrations, checkout changes or changes to shared dynamic-content logic.
  • Keep performance healthy by limiting app scripts, optimizing media, testing mobile and reviewing metrics after each release.
  • Keep security healthy through two-step authentication, least-privilege access, app review and controlled credential rotation.
